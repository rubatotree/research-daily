# 公开内容安全与隐私红线

`research-daily` 仓库与 GitHub Pages **公开**。任何写入 `digests/`、`meta/`、前端资源的内容，都按「会被陌生人全文阅读、被搜索引擎收录」处理。

## 绝不提交 / 绝不写进日报

| 类别 | 例子 |
|------|------|
| 密钥与会话 | API key、token、cookie、SSH 私钥、`.env`、OAuth refresh |
| 账单与额度 | X / API credits、费用、配额耗尽提示 |
| 未公开研究 | 未披露实验数字、内部消融、未公开手稿、组会未公开材料 |
| 私人信息 | 手机、私人邮箱、住址、证件、健康信息 |
| 内部实现细节 | 自动化内部 ID、本机绝对路径、具体 connector/tool 调用参数 |
| 过程水印 | 「非本窗口」、检索调试日志、`max_results` |

## 可以公开写

- 已在 arXiv / 会议 / 项目页公开的论文信息与配图（注意版权：嵌入公开 teaser/pipeline，并链回原文）
- 维护者已在 blog / academic / 主页公开的身份与研究方向
- 对公开论文的中文摘要转述、方法概要、对照阅读建议（基于公开文本）

## 写作自检（发布前）

1. 文中是否出现 token、密码、额度数字？→ 删
2. 「值得关注」是否泄露未公开实验？→ 改成公开对照表述
3. 配图是否来自公开 PDF/项目页？→ 否则不嵌
4. `seen-papers.json` 是否只有论文元数据？→ 是
5. 提交前 `git status` / `git diff` 是否误加私密文件？→ 撤出

## 事故响应

若误推密钥：立刻轮换该密钥；从 git 历史移除（`git filter-repo` / 联系 GitHub 支持）；在私聊通知维护者。不要只靠「再 commit 删掉文件」。
