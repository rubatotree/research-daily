# 日报规范

## 公开安全（必读）

本仓与 Pages **公开可读**。写入 `digests/`、`meta/`、README 时遵守：

**禁止写入公开文件**
- 密钥、token、cookie、`.env`、私钥、API 额度 / credits / 账单
- 未公开的实验数字、内部评审意见、未发表手稿全文、私人通信
- 个人敏感信息（手机、私人邮箱、住址、证件号等）
- 平台内部工具名、agent/自动化内部 ID、本机绝对路径（接管文档用角色与意图描述即可）
- 检索过程备注（「非本窗口」、`max_results`、tool 名等）

**允许写入**
- 已公开学术身份与实验室归属（以 blog / academic / 个人主页为准）
- 公开论文、开源仓库、会议录用等公开事实
- 研究方向与课题焦点的**公开表述**（如 Real→Sim→Real、可重光照 3DGS），勿写未公开的具体实验配置或未披露结果

拿不准：默认不写进公开仓；可只在与用户的私聊里说明。

## 成稿形态（完整版）
- 今日速览 / 总体总结：有判断、点名必读；文笔自然，像研究笔记
- 主题分块用自然语言标题（如「逆渲染与材质」「正向渲染效率」「可编辑动态资产与绑定」「具身数据增强与回环」）
- 正文**不要**标注 `[A]` / `[B]` / `[C]`（内部仍可按拆分绑定 / 正向效率 / 逆渲染加权）



## 写作前检查长期记忆（每日必做）
动笔写当日日报**之前**必须：
1. 阅读并核对 `meta/LONG_TERM_MEMORY.md`、`digest-spec.md`、`research-interests.md`、`failover.json`、`privacy.md`、`seen-papers.json`
2. 对照 `rubatotree/blog` / `academic` 近期 commits：若兴趣、规范、故障转移名册或流程有变，**先更新**相应 `meta/` 文档并提交，再写日报
3. 无变更则不必空改；有变更须写进公开记忆（遵守 `privacy.md`），避免只改私聊、仓内过时

## 协同 Bot 文风学习（必做）
加入协同维护的 Bot，在撰写**当日**日报前必须：
1. 打开近几天（建议至少 **3** 篇）`digests/`，优先读 **编写署名不是自己** 的篇目
2. 学习基本写法与优点：今日速览的判断力与结构、分块小结、方法概要/值得关注的信息密度、锚点与标题栏（短名 · Venue · 日期）、覆盖说明与署名习惯
3. **允许**在清晰前提下做风格创新，不必逐句模仿
4. **目标：** 尽可能清晰易读；概括与重点分明（必读先点名、原因一句说清）；避免流水账与空话

主责 Bot 亦应定期回看他人接管稿，吸收优点并保持规范字段完整。

## 论文标题栏（目录可见）

三级标题格式（会进入站点 TOC）：

```text
### 短名 · Venue或arXiv · YYYY-MM-DD
```

示例：
- `### LightBridge · arXiv · 2026-09-02`
- `### UniMate · SIGGRAPH Asia 2026 · 2026-09-04`
- `### TileGS · Pacific Graphics 2026 / CGF · 2026-09-03`

规则：
- 已接收会议/期刊：写正式 venue 名 + arXiv 挂出日（或正式发表日，若已知且更准）
- 仅预印本：`arXiv · 首次挂出日`
- 标题上方保留稳定锚点：`<a id="slug"></a>`
- 正文仍保留完整 **发表时间** / **投稿信息** 字段，供细读；TOC 靠标题栏一眼看到会议与时间
- 圈内动态等非论文小节（媒体 / X / Ke-Sen 等）不要硬套「· Venue · 日期」

## 每篇必含字段
1. 一句话判断要点（标题下首段）
2. Title（英文全名）
3. 作者（英文 / 拼音，不译成中文姓名）
4. 单位（仅确定国内机构用中文；不确定保留原文）
5. 投稿信息（已接收 / 推测+依据 / 未标明；禁止把推测写成已中）
6. 发表时间（预印本：arXiv 首次挂出日；已发表：会议/期刊时间）
7. arXiv abs / PDF（或其它稳定入口）
8. 摘要中译
9. **方法概要**（尽量基于全文 / HTML，勿只靠摘要臆造模块）
10. **值得关注**（相对公开研究方向的对照阅读建议；勿泄露未公开实验）
11. 相关链接（主页 / 代码 / 视频；找不到如实写）
12. 配图嵌入正文（pipeline / teaser；必读至少 1 张）

## 去重
- 清单：`meta/seen-papers.json`（与 Bot 侧 ledger 同步）
- 默认不重复收录
- 例外须注明「为何重提」：新版本、新录用、重要开源、圈内新观点/新影响
- 「新兴趣相关」可重复、可不限近日；须标明为何与兴趣相关


## 圈内动态 / 公众号（观点提炼）
中文科技媒体、公众号、PaperWeekly 类、X 关键词等**不要只贴标题+链接**。每条尽量写清：
1. **事实**：谁、发了什么（论文/开源/产品/讨论）
2. **有价值的观点或判断**：作者或社区在主张什么、和既有路线差在哪（1–3 句）
3. **与本刊兴趣的对照**（可选一句）：为何值得 PTIR-GS / Real2Sim / 3DGS / 具身读者留意
无高信号则写「本日无高信号圈内条目」，禁止注水；过程与额度不入库。

## 信息源
- arXiv（cs.GR + 关键词漏斗）与 Ke-Sen
- GitHub：`rubatotree/blog`、`rubatotree/academic`（以 **commits** 校准兴趣，不只看 Pages）
- 机器之心 / 量子位 / 新智元；PaperWeekly 类
- 公开搜索（Scholar / 网页）
- X：关键词检索（估成本；**过程与额度不写进正文或公开 meta**）

## 节奏
- 每天 04:00（Asia/Hong_Kong）生成并推送本仓 / Pages
- 自 2026-09-08 起须稳定执行

## 版式顺序
1. 标题（`# YYYY-MM-DD 科研日报` 或等价）
2. **今日速览**（置顶；论文名用 markdown 链到锚点）
3. 各主题正文
4. 圈内动态 / 新兴趣相关（如有）
5. 文末 **覆盖说明**（覆盖窗口、数据完备性等元信息放这里）
6. 覆盖说明末行必须写 **编写：** `<bot代号>`（该篇实际执笔者的公开代号，来自作者私有记忆；例：`**编写：** Cream`）
7. 不要写「读者：…」；不要写「策展版 vN 生成：…」类水印页脚

## 日期约定
- **日报日期**（文件名 `digests/YYYY-MM-DD.md`、站点选日）= **发布日**（通常为早上 4:00 HKT）
- **内容覆盖** = **前一自然日**的新内容（例如 9 月 7 日日报写 9 月 6 日新稿）
- 文末「覆盖说明」同时写明日报日期与内容覆盖日；周末等无独立 arXiv 公告时，可纳入相邻公告日积压，但发布日仍用当日
- `digests/index.json` 条目建议含 `content_day`

## 禁止写入正文的过程信息
- 「非本窗口」等内部策展切口
- X/API 余额、tool 名、`max_results`、credits 等检索过程备注
- 任何密钥或可识别私密路径

## 编写署名
- 每篇日报在文末「覆盖说明」最后一行写：`**编写：** <代号>`
- 代号必须与 `meta/failover.json` 名册中的某个 `code` 一致，且等于**本篇实际编写者**私有记忆中的代号
- 这是单篇归因，不是把「你是某某」写进通用接管文案；其他 Bot 不得照抄别人的代号署名

## Git 提交署名
向 `rubatotree/research-daily` 提交时，若维护 Bot 有公开代号，须在 **commit message 的 description（正文，非仅 subject 一行）** 中署名，例如：

```text
Require viewpoint distillation for community digests

Rewrite 圈内 with fact/viewpoint/contrast; update specs.

编写：Cream
```

或单独一行 `Signed-off-by-bot: Cream` / `Bot: Cream`。日报文末 `**编写：**` 与 commit description 署名应一致（同一次发布）。无代号的人类提交可省略。
